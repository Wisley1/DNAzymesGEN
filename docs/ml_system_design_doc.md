# ML System Design Doc - [RU]

## Пайплайн по открытию новых каталитических ядер ДНКзимов, используя генеративные методы и иерархический скрининг

### Глоссарий

Короткие имена из текста. Расшифровка дана в том смысле, в каком термин используется в этом пайплайне.

| Термин | Что это |
| --- | --- |
| ДНКзим | Цепь ДНК, которая разрезает РНК. В природе таких молекул нет, их синтезируют в лаборатории. |
| Каталитическое ядро | Средний участок ДНКзима, который делает разрез. Генератор предлагает только его. Руки, которые держат РНК, пристраивают после отбора. |
| SequenceCraft | Экспериментальный набор известных ядер и единственный источник измеренной активности. В файле 549 строк и 349 разных ядер. |
| \(k_\mathrm{obs}\) | Измеренная скорость расщепления, мин⁻¹. Для классификатора активное ядро — запись с \(k_\mathrm{obs} > 1 \times 10^{-7}\). Таких ядер 161. |
| EDS | Evolutionary Distribution Synthesis. Синтетический корпус для предобучения: длина, доля G и C, разнообразие букв и расстояние до ядер повторяют SequenceCraft. Файл `Data/EDS/distrib_result.csv`. |
| MFE | Minimum Free Energy, минимальная свободная энергия складывания, ккал/моль. Ниже — укладка устойчивее. Корпус MFE — синтетические цепи с энергией ниже −10. Файл `Data/MFE/seq2 - seq2.csv`. |
| WGAN-GP | Генератор цепей: Wasserstein GAN с gradient penalty. Предобучение на EDS или MFE, затем дообучение на SequenceCraft. |
| JSD | Jensen–Shannon divergence. Насколько расходятся два распределения коротких кусков. Здесь сумма по кускам из 1, 2, 3 и 4 букв. Меньше — ближе к обучающему набору. По этой сумме выбраны сохранённые модели. |
| Levenshtein | Число замен, вставок и удалений, чтобы из одной цепи получить другую. В отборе его делят на длину более короткой цепи и оставляют первый квартиль: четверть цепей, ближайших к SequenceCraft. |
| TDE | Tree edit distance. Число правок, чтобы скобочную запись укладки одной цепи превратить в укладку ядра SequenceCraft. Меньше — вторичная структура ближе. После фильтров берут десять цепей с наименьшим TDE. |
| In-line атака | Геометрия разреза РНК: кислород при 2'-углероде, фосфор в месте разреза и уходящий кислород стоят почти на одной линии. На шортлисте AlphaFold 3 проверяет, собрана ли эта линия. Это проверка геометрии, отдельная от измеренной скорости. |
| AlphaFold 3 (AF3) | Модель трёхмерной укладки. Здесь ею снимают вторичную структуру и проверяют геометрию in-line атаки на коротком списке кандидатов. |
| 10–23 | Известный ДНКзим. По его схеме к отобранному ядру с двух сторон пристраивают короткие руки, комплементарные РНК. |

### 1. Цели и предпосылки

#### 1.1. Зачем идем в разработку продукта?

- Бизнес-цель: ускорить поиск новых каталитических ядер ДНКзимов de novo, сократив пул кандидатов от огромного списка до шортлиста с кандидатами, которые стоит проверить в лаборатории, полученные с использованием генеративного и классического подходов ML с учетом эвристических доменных правил и анализа геометрии молекулы.  Запрос возник из-за того, что дизайн ДНКзимов не имеет универсальных правил, эти молекулы в природе не существуют, открыты относительно недавно и синтезируются исключительно в лаборатории для таргетной диагностики или для лечения генетических заболеваний.
- Почему станет лучше, чем сейчас, от использования ML : вместо использования ограниченного набора известных последовательностей генератор предложит ядра за пределами тренировочного набора данных (novelty), синтетические набора данных, основанные на термодинамических и статистических показателях, позволят качественно обучить модель. Вместо полной лабораторной проверки кандидатов иерархических скрининг значительно сужает пространство для синтеза, что ускоряет и удешевляет эксперименты. Кратко: затрат на пустые эксперименты меньше, выхлоп по качеству больше из-за обоснованного пайплайна.
- Что будем считать успехом итерации с точки зрения бизнеса: Для этой итерации (то, что уже сделано в статье) успех - рабочий discovery-loop, который выдаёт проверяемые кандидаты:
  1. Пайплайн воспроизводим (за исключением этапов AlphaFold): pre-train → fine-tune → генерация → скрининг → структурный отбор.
  2. Fine-tune после синтетического pre-training даёт больше кандидатов, прошедших иерархический фильтр, чем обучение только на SequenceCraft и чем случайная ДНК.
  3. На выходе есть короткий шортлист для проверки в лаборатории с геометрическими основаниями; в статье это три дизайна в порядке приоритета: EDS39T1S1, MFE123T1S1, MFE191T1S2.
  4. Зафиксированы ограничения: AF3-геометрия ≠ измеренная активность; контроль 10–23 окнами не воспроизводится; cleavage rates ещё не измерены.

#### 1.2. Бизнес-требования и ограничения

- Краткое описание БТ и ссылки на детальные документы с бизнес-требованиями : система должна предлагать новые каталитические ядра ДНКзимов вне тренировочного набора данных (набор SequenceCraft). После иерархического отбора возвращать шортлист на синтез и лабораторную проверку. Генерация производится не под конкретную РНК: мишень мы берем на этапе проверки и подбираем к ядру руки, комплементарные РНК. Отдельно сравниваются стратегии предобучения и оценка вклада дообучения моделей для понимания масштабирования обучения при дефиците размеченных данных. Детальные документы с бизнес-требованиями можно найти в тезисах к конференции (указано в README).
- Бизнес-ограничения : реальных экспериментально проверенных ядер мало (набор SequenceCraft около 500 шт); геометрия в AF3 и прохождение установленных фильтров не означают доказанную каталитическую активность; вычисления в AF3 ограничены - сложно, немассово, затратно по ресурсам; синтетические наборы данных и классификатор (этап в скрининге) наследуют биас SequenceCraft (ключевой трейн и референс в работе)
- Что мы ожидаем от конкретной итерации: Воспроизводимый цикл: предобучение, дообучение, генерация, скрининг, структурный отбор. Дообучение после синтетического предобучения пропускает через фильтры больше кандидатов, чем обучение только на SequenceCraft и чем случайная ДНК. На выходе есть короткий шортлис с геометрическими основаниями. В статье это EDS39T1S1, MFE123T1S1 и MFE191T1S2. Измеренные скорости расщепления в эту итерацию не входят: это уже пилот.
- Описание бизнес-процесса пилота, насколько это возможно - как именно мы будем использовать модель в существующем бизнес-процессе?   Запуск генерации ядер; автоматический скрининг (вмешательство только на этапах AF3), создание шортлиста ядер, дополнительный этап связан с финальной проверкой на тестовых РНК-сайтах для приоритезации кандидатов; передача в лабораторию.
- Что считаем успешным пилотом? Критерии успеха и возможные пути развития проекта: на приоритетных вариантах обучения модели иерархический скриниг отсекает меньше последовательностей, чем на пуле случайно сгенерированных последовательностей; моделирование геометрии в AF3 в шортлисте дает основания для экспериментальной проверки хотя бы одного кандидата; иерархический пайплайн обоснован, включает в себя всесторонние проверки и сокращает в значительной степени пул кандидатов (из 250к остаются десятки-сотни)  
Пути развития:
  1. Провести экспериментальную лабораторную проверку, для AF3 взять больше мишеней.
  2. Условно генерировать / ранжировать под РНК (сейчас этого нет).
  3. Ослабить зависимость от тяжёлого AF3 там, где хватает дешёвых фильтров (переход на boltz).
  4. Упаковать пайплайн в повторяемый внутренний сервис.

#### 1.3. Что входит в скоуп проекта/итерации, что не входит

- На закрытие каких БТ подписываемся в данной итерации:
- De novo генерация каталитических ядер (WGAN-GP): synthetic pre-train (MFE и/или EDS) → fine-tune на SequenceCraft → генерация пулов.
- Иерархический *in silico* отбор без привязки генерации к конкретной РНК: классификатор активности → близость к SequenceCraft → эвристики вторичной структуры / TDE → shortlist.
- Сравнение стратегий pre-training (MFE vs EDS vs SC-only / random) в терминах сколько кандидатов проходит фильтры и distributional fidelity к SequenceCraft.
- Приоритизация шортилста для лаборатории с геометрическими основаниями (AF3 на ограниченном стенде мишеней) - как этап оценки, не как условие обучения.
- Воспроизводимый пайплайн в репозитории: данные, чекпоинты, скрипты train/generate/screen, зафиксированный шортлист (EDS39T1S1, MFE123T1S1, MFE191T1S2).
- Что не будет закрыто :
- Измеренные cleavage rates / лабораторная проверка (это пилот после *in silico* итерации).
- Генерация или ранжирование, обусловленные конкретной РНК на входе модели.
- Калиброванный предиктор kobs и замена assay геометрией AF3.
- Production-сервис (API, SLA, онлайн-инференс, мониторинг дрейфа).
- Масштабный AF3-скрининг всего сгенерированного пула.
- Описание результата с точки зрения качества кода и воспроизводимости решения :
- Публичный репозиторий с README и `generated/WORKFLOW.md`: сценарии pretrain / finetune / generation / evaluation / screening.
- Зафиксированные артефакты: датасеты в `Data/`, чекпоинты в `checkpoints/` (Git LFS), выходы генерации и скрининга в `generated/`.
- Dev-гигиена: `ruff` (`pyproject.toml`), `requirements-dev.txt`, `pre-commit` (lint+format на `.py`, без автофикса ноутбуков).
- Воспроизведение ядра пайплайна (train → generate → screen) с GPU + заявленными зависимостями; AF3 — отдельный, документированно тяжёлый/внешний шаг.
- Описание планируемого технического долга (что оставляем для дальнейшей продуктивизации):

| Долг                                                                                  | Зачем откладываем                                                                                                              |

#### 1.4. Предпосылки решения

- Объект: моделируем каталитическое ядро. Так бизнес получает шортлист: руки и мишень собираются после отбора.
- Блоки данных:

| Блок          | Что это                                                                                     | Зачем                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| SequenceCraft | около 549 систем; для классификатора 161 активных ядер с \(k_\mathrm{obs}\) выше порога     | единственный размеченный позитив для fine-tune и фильтра                               |
| Synthetic MFE | большой корпус с термодинамическим трешхолдом (значения ниже -10)                           | pre-train при нехватке экспериментальных ядер, основанная на свойствах геометрии цепей |
| Synthetic EDS | корпус, согласованный с распределением SequenceCraft                                        | вторая стратегия pre-train для сравнения                                               |
| Негативы      | около 1000 случайных последовательностей для LightGBM; пул 250 тысяч как контроль пайплайна | контраст для классификатора и бейзлайн случайная ДНК                                   |
| Стенд РНК     | несколько сайтов (EIF3C, WT KRAS) и arms по конвенции 10–23                                 | только приоритизация в шортлисте через AF3                                             |

- Горизонт: календарного прогноза нет. Один цикл - pre-train, fine-tune, генерация около 250 тысяч ядер на вариант обучения, скрининг и шортлист. Пересчёт делается новой кампанией, когда появляются метки из лаборатории или меняется стратегия pre-train.
- Гранулярность: генерация и фильтры работают на одну последовательность ядра. Классификатор выдаёт вероятность активности на последовательность (на генерации порог 0.95). После шортлиста единица - конструкт: левая рука, ядро, правая рука и выбранный сайт. Бизнес-выход итерации - ранжированный шортлист, не прогноз \(k_\mathrm{obs}\).
- Допущения: synthetic pre-train и fine-tune на малом assayed-наборе достаточны, чтобы предлагать ядра вне SequenceCraft и при этом близкие к нему по составу и вторичной структуре. Эвристики (Levenshtein Q1, стебли, шпильки, tree edit distance) отражают правила SequenceCraft и сокращают число синтезов. Прохождение фильтров и геометрия AF3 - приоритизация, не метка активности. Сравнение MFE и EDS нужно, чтобы выбрать, как масштабировать обучение при дефиците данных. Честное сравнение - те же фильтры на модели, обученной только на SequenceCraft, и на случайной ДНК.

### 2. Методология

#### 2.1. Постановка задачи

- Постановка `задачи`:  генерация и иерархический отбор кандидатов. Нужно из пространства последовательностей ДНК получить короткий список новых каталитических ядер, которые стоит синтезировать.
- Две модели:
  1. **WGAN-GP** учит распределение ядер: pre-train на MFE или EDS, fine-tune на SequenceCraft, затем генерация.
  2. **LightGBM** - бинарный фильтр "похоже на активное ядро / нет". Обучается на 161 позитивах SequenceCraft и случайных негативах.
- Дальше детерминированные фильтры: нормализованный Levenshtein к SequenceCraft (первый квартиль), правила вторичной структуры, ранжирование по tree edit distance. На ограниченном стенде мишеней top-ядра собираются с руками и оцениваются в AlphaFold 3 по геометрии in-line атаки.
- Бейзлайны на том же скрининге: WGAN, обученный только на SequenceCraft, и случайная ДНК. Успех MVP относительно них же - больше последовательностей проходит иерархический фильтр, и на выходе есть шортлист с геометрическими основаниями для лаборатории.
- Выход: ранжированные ядра. В текущем прогоне это EDS39T1S1, MFE123T1S1 и MFE191T1S2.

#### 2.3. Этапы решения задачи

Дальше два пути. Основной — уже собранный пайплайн: предобучение, дообучение, генерация, отбор, короткий список для лаборатории. Сравнение — случайная ДНК без модели, через те же фильтры до вторичной структуры. Отдельно есть генератор, обученный только на SequenceCraft: тот же отбор, без дерева структур и без AlphaFold 3.

##### Этап 1. Подготовка данных

Генератору не нужна колонка с ответом: он учится, как выглядят последовательности. Классификатор отвечает, похожа цепь на активное ядро или нет. Число активности \(k_\mathrm{obs}\) есть только у SequenceCraft. По нему отобрали более активные ядра: активность выше \(1 \times 10^{-7}\).

| Данные | Файл | Что это | Качество проверено |
| --- | --- | --- | --- |
| SequenceCraft | `Data/Sequence_Craft/SequenceCraft_dataset.csv`, колонка `e`, рядом `kobs` | 549 строк, 349 разных ядер. Единственный экспериментальный набор | да |
| MFE | `Data/MFE/seq2 - seq2.csv`, колонка `Sequence` | 232 885 синтетических цепей для предобучения | да. Самого числа энергии в файле нет |
| EDS | `Data/EDS/distrib_result.csv`, колонка `sequence` | 277 765 синтетических ядер для предобучения | да |
| Негативы для бейзлайна | `Data/Negatives/dna_sequences.csv` | 250 000 случайных ДНК | да, файл собирается скриптом заново |
| Негативы для классификатора | отдельная выборка около 1000 случайных ДНК | примеры «не ядро» при обучении | это не пул 250 тысяч |

Пустых строк и букв кроме A, C, G, T нет. Готовых ядер SequenceCraft в трёх синтетических файлах нет.

Что видно по данным:

- В предобучении не ровно 250 тысяч строк: так получилось при сборке. MFE — 232 885, EDS — 277 765, негативы — ровно 250 000.
- SequenceCraft — это 349 ядер, а не 549 строк. 200 строк повторяют уже встреченные ядра, 14 последовательностей встречаются больше одного раза, одна — 41 раз. У 13 таких ядер в разных строках записана разная активность. Повтор усиливает ядро при дообучении, а одну активность по последовательности уже не восстановить.
- EDS повторяет SequenceCraft. Длина та же: медиана 40, квартили 37 и 49. Доля G и C и разнообразие букв внутри цепи лежат рядом с экспериментальными ядрами. Точных копий этих ядер в файле нет. В статье у этого корпуса длина от 14 до 80, расстояние редактирования от 22 до 47, доля G и C от 20 до 80 процентов, разнообразие букв от 1.5 до 2.
- MFE собран по другому правилу. Берём цепи, которые хорошо складываются: свободная энергия ниже −10 ккал/моль. У SequenceCraft средняя энергия около −7.5, у ядер с марганцем около −8.7, поэтому −10 взят с запасом, на устойчивую сторону от этого среднего. Такие цепи длиннее и богаче G и C: медиана длины 71, доля G и C 0.55. Это не копия SequenceCraft.
- Негативы — бейзлайн. Медиана длины 40, все четыре буквы поровну. До ближайшего экспериментального ядра им дальше, чем ядрам друг до друга.

Откуда берутся файлы:

- SequenceCraft — таблица эксперимента из одноимённой статьи. Она идёт и в классификатор, и в дообучение.
- Негативы для бейзлайна собираются здесь: `scripts/generation/generate_negative_dna.py`. Длина берётся из гладкого распределения Beta(7.0, 7.5) и укладывается в отрезок от 8 до 74 букв. Буквы выбираются поровну и независимо. Seed 12345, 250 000 строк. Запуск ручной.
- Негативы для классификатора — другой запуск: длина берётся из длин активных ядер, seed 42, около 1000 цепей.
- EDS и MFE собраны отдельно. Скрипты лежат в закрытом репозитории, в этот форк я их не клал. Как устроен отбор, написано в тезисах, на которые я ссылался в комментарии к PR1.
- Пулы около 250 тысяч на схеме основного решения — это уже выход генератора, этап 3.

Экспериментальных ядер мало, чтобы учить генератор только на них. Поэтому перед дообучением модель смотрит большой синтетический набор.

EDS для этого повторяет SequenceCraft: длину, долю G и C, разнообразие букв в цепи и расстояние редактирования до экспериментальных ядер. Модель видит много цепей того же профиля и при этом не получает готовые лабораторные последовательности.

MFE учит другому. Поиск перебирает буквы и оставляет цепи с энергией складывания ниже −10. На каждом шаге остаётся 90 процентов лучших. Так в предобучение попадают устойчиво сложенные цепи, а не случайный текст.

Негативы нужны как сравнение. Это случайные цепи с длиной в том же диапазоне, что у SequenceCraft, и с равными долями букв. На длине, доле G и C, разнообразии букв и расстоянии до ядер их ставят рядом с SequenceCraft. Этот же файл идёт в отбор без модели.

На выходе этапа для основного решения — четыре корпуса: SequenceCraft как эксперимент, EDS как его повтор для предобучения, MFE как набор устойчиво сложенных цепей, негативы как контроль. Для бейзлайна — 250 000 случайных цепей и то же сравнение с SequenceCraft.

##### Этап 2. Подготовка моделей

Модели две.

Генератор учится выдавать новые цепи, похожие на обучающий набор. Во время обучения смотрим, насколько короткие куски из 1–4 букв в новых цепях похожи на куски обучающего набора. Чем меньше расхождение, тем ближе набор. Это число — сумма четырёх таких расхождений, JSD. По нему выбраны сохранённые модели. Для EDS взята модель на шаге 1400 (JSD 0.0235 на итерации 1399, лог `checkpoints/eds/train.log`, модель `checkpoints/eds/model-1400`): дальше она начинала запоминать сам синтетический корпус. Для MFE взята модель на шаге 3000 (JSD 0.0095 на итерации 2999, лог `checkpoints/mfe/train.log`, модель `checkpoints/mfe/model-3000`), у неё расхождение было наименьшим. Предобучение идёт 3600 шагов. Дообучение на SequenceCraft — 1000 шагов, шаг обновления в два раза меньше, чем при предобучении. Для обоих дообучений оставлена модель на последнем шаге (EDS: JSD 0.0326, лог `checkpoints/eds_ft/train.log`, модель `checkpoints/eds_ft/model-999`; MFE: JSD 0.0437, лог `checkpoints/mfe_ft/train.log`, модель `checkpoints/mfe_ft/model-999`). Для варианта только на SequenceCraft — модель на шаге 700 (JSD 0.0335 на итерации 699, лог `checkpoints/sequence_craft/train.log`, модель `checkpoints/sequence_craft/model-700`), у неё расхождение было наименьшим.

Для уже готового пула этого мало. Дополнительно смотрим длину, долю G и C, разнообразие букв внутри цепи и расстояние до ближайшего ядра SequenceCraft. Точных копий экспериментальных ядер в пуле быть не должно.

Классификатор сначала превращает цепь в набор чисел моделью DNABERT, затем по этим числам решает «похоже на активное ядро» или нет. На сгенерированных цепях оставляем те, у которых вероятность активного класса не ниже 0.95. Обучающая выборка: 161 ядро SequenceCraft с активностью выше \(1 \times 10^{-7}\) и около 1000 случайных цепей. 80 процентов уходит в обучение (129 активных и 799 случайных), 20 процентов — в проверку (32 и 201). Перебраны разные способы превращения цепи в числа, здесь описан итоговый.

Проверка простая: сколько настоящих ядер классификатор зря отбрасывает. Числа — дополнительная таблица S3. Отдельного файла с ней в репозитории нет. ROC AUC от порога не зависит, поэтому у одного split она в обеих строках одинаковая. Строка Train+Test считает и те цепи, которые уже были в обучении.

На SequenceCraft при пороге 0.95 зря отброшены 30 ядер из 161, ложных срабатываний нет. При пороге 0.50 таких ядер 25, но 12 неактивных приняты за активные. На test при пороге 0.95 из 32 активных остаются 2, ложных срабатываний тоже нет. Порог 0.95 выбран так, чтобы неактивная цепь не проходила, даже если часть настоящих ядер отсеется.

Как делим данные:

- SequenceCraft нельзя резать по строкам файла. Одна и та же последовательность попадёт и в обучение, и в проверку, а у части повторов ещё и разная активность. Делим по уникальным ядрам.
- Случайные цепи для обучения классификатора и пул 250 000 — разные запуски. Иначе бейзлайн уже был бы виден модели (активные сиквенсы из референса считаем допущением, продиктованным недостатком данных). Порог 0.95 смотрим и на отложенных ядрах, и отдельно на случайной ДНК.

Бейзлайн со схемы модель не учит. Берётся файл негативов из этапа 1. Дальше тот же классификатор и те же правила, что у основного решения, до вторичной структуры. Сравниваем, сколько цепей осталось.

Второй бейзлайн учит генератор только на SequenceCraft, без MFE и EDS. Отбор тот же. Дерево структур и AlphaFold 3 в этот счёт не входят.

Дальше на одном и том же отборе сравниваются предобучение на EDS, предобучение на MFE, генератор только на SequenceCraft и случайная ДНК.

По готовому пулу видно, близок ли он к 349 ядрам по длине, доле GC, разнообразию букв и расстоянию редактирования, и нет ли среди него точных копий. По классификатору видно, на каком пороге цепь выбыла. Вероятность 0.95 — это порог отсечения.

Риски:

- Дообучение на сотнях ядер может их запомнить. Это видно по точным совпадениям с SequenceCraft в пуле. Шаг обновления на дообучении поэтому меньше, чем на предобучении.
- EDS переносит профиль SequenceCraft. После дообучения пул сверяют и с ядрами, и с негативами.
- MFE длиннее SequenceCraft, медиана 71. После дообучения легко получить цепи не той длины.
- Порог 0.95 и отбор четверти самых близких по буквам (Левенштейн) не привязаны напрямую к измеренной активности. Сравнение честное только если все варианты проходят одну и ту же цепочку фильтров.

Результат этапа для основного решения — выбранные модели предобучения и дообучения и правило, как сравнивать пул с ядрами. Результат для бейзлайна — пул случайных цепей с длиной в границах SequenceCraft и, отдельно, модель, обученная только на SequenceCraft. Оба готовы к одному и тому же отбору.

##### Этап 3. Генерация пула

Основной генератор выпускает около 250 тысяч ядер на каждый вариант: предобучение на MFE или на EDS, затем дообучение. Бейзлайн со схемы этот этап пропускает и подставляет файл негативов. Генератор только на SequenceCraft выпускает свой пул того же размера.

Результат — таблица последовательностей на каждый вариант. Точных копий SequenceCraft в ней нет. Длина и состав считаются так же, как на этапе 1. Это вход отбора, ещё не короткий список.

Риск: после дообучения пул может отойти от своего предобучения или, наоборот, слишком прижаться к SequenceCraft. Это видно по тем же сравнениям, что на этапе 1. В этой задаче сдвиг в сторону экспериментальных ядер считаем хорошим знаком: новых измеренных ядер мало, и близость к ним как раз то, что мы ищем. Точные копии при этом по-прежнему не нужны. Это осознанное допущение в рамках этой задачи.

##### Этап 4. Иерархический отбор

Одна цепочка и для основного решения, и для обоих бейзлайнов:

1. Классификатор. Оставляем цепи с вероятностью активного класса не ниже 0.95.
2. Близость букв к SequenceCraft. Для каждой цепи считаем, сколько правок нужно, чтобы получить ближайшее экспериментальное ядро, и делим это число на длину более короткой из двух цепей. Оставляем четверть самых близких в этом пуле.
3. Вторичная структура. Её снимаем с модели AlphaFold 3 для цепей, которые уже прошли два фильтра выше. Убираем цепи без пар, стебли длиннее 9 букв и шпильки, чей центр вылезает за окно SequenceCraft: от 0.236 до 0.791 длины цепи. Длина шпильки при этом от 3 до 12, длина стебля от 1 до 9. Правила выведены при анализе структур SequenceCraft.

На этом бейзлайн останавливается. Считаем, сколько цепей осталось и на каком фильтре остальные выбыли. В основном решении прошедшие ещё сортируются по тому, насколько их укладка в скобках похожа на укладки SequenceCraft. Чем меньше правок в этой укладке, тем выше цепь. Десять лучших идут дальше, в AlphaFold 3 уже вместе с РНК.

Четверть самых близких считается внутри своего пула. Каждый пул отдаёт около четверти тех, кто прошёл классификатор, поэтому одно только число прошедших этот фильтр не говорит, чей пул ближе к ядрам. Рядом записываем сами расстояния.

Результат бейзлайна — число оставшихся после вторичной структуры и разбивка потерь по трём фильтрам. Результат основного решения — тот же счёт плюс список десяти цепей на вариант обучения.

##### Этап 5. Сборка с руками и проверка геометрии

Этот этап есть только у основного решения. К ядру с двух сторон пристраиваются короткие руки по правилу известного ядра 10–23. Руки комплементарны РНК и сами по себе ядро не меняют. Мишени фиксированные, с известным местом разреза: фрагмент EIF3C и фрагмент KRAS дикого типа. Длину руки выбираем так, чтобы температура плавления пары была ближе всего к 37 °C. AlphaFold 3 смотрит, выстроены ли атомы в месте разреза для атаки. В текущем прогоне в приоритете три конструкции: EDS39T1S1, MFE123T1S1 и MFE191T1S2.

AlphaFold 3 дорогой, поэтому сюда не идёт весь пул и не идёт бейзлайн. Счёт «сколько прошло фильтры» уже есть на этапе 4. Красивая геометрия не заменяет измеренную скорость разрезания. Контроль тем же окном 10–23 в модели не воспроизводится: это ограничение итерации, а не критерий обучения.

Результат — короткий список на синтез для лучших вариантов обучения. В него попадают цепи, которые и по статистике близки к SequenceCraft, и оставили после фильтров больше образцов, чем случайная ДНК. К пилоту готовы, если хотя бы у одного кандидата геометрия в месте разреза выглядит пригодной и его вариант обучения прошёл этап 4 лучше случайной ДНК.
